MQTT playground

A preview of the browser client. Working: connect over WebSocket, text password, a retained Will, subscribe at QoS 0 and 1, publish text at QoS 0 and 1 with retain, reconnect after a lost connection, a check when the page comes back, drained disconnect and stable error codes. Not yet: QoS 2. The client can also resume a session with resume. This page does not use it, so each connection starts a new session.

Both modes use createReconnectingClient. The scripted broker can end its connection, and a publication to playground/unacknowledged at QoS 1 never gets a PUBACK, so a drop lists it as uncertain. A drop also makes the scripted broker publish the Will.

The first retry waits 2.5 to 5 seconds. "Retry now" calls retryNow(), which starts the next attempt at once while the client waits and returns false otherwise. watchPageLifecycle checks the connection when the page comes back after it was hidden, frozen or kept in the back-forward cache, and the list shows each return.
