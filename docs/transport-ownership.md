# Transport and session ownership

The TCP, Node WebSocket and browser factories pass native connections to the same byte transport core. Custom byte transports use that core through `createTransportClient`. Adapter options control the native connection. Session options control MQTT exchanges. [Byte transport contract](byte-transport.md) · [Public types](public-types.md)

## Publish and close paths

A QoS 1 publish validates the topic and reserves application capacity. `OutboundQosOne` waits for a broker slot, leases an identifier, and installs the exchange before sending. The core encodes the packet and checks native capacity before calling `ByteWriter.write`. The inbound path frames the reply and hands the PUBACK to the exchange. A matching broker acknowledgment and settled write release the exchange. The byte reservation remains until the write settles, including when a terminal error has already reached the caller. [QoS 1 publish](qos1-publish.md) · [Outgoing admission](outgoing-admission.md)

When the transport fails during DISCONNECT, `PacketInput` records the input cause and the session reports it to pending operations and the end observer. The core starts the forced writer close. If session shutdown reaches the same forced-close path, it waits for that operation. A native failure during a graceful close can still escalate it. The held shutdown write, refused connection and handoff abort each requested two forced closes before the change. Each now requests one.
